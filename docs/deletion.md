# 草稿回收站与永久删除

升级后执行 `ainovel init-db` 增加 `resource_deletions` 表，再重启 API 和 Worker。初始化不删除已有作品。

## 可恢复删除

书架的创作草稿卡片提供「删除」。小说沿用工作区侧栏的「移入回收站」。书架回收站同时显示两者，并支持恢复；空回收站也可以正常打开和关闭。

草稿通过 `set_setup_draft_deleted` 命令删除或恢复，使用草稿 ID 作为 `session_id`。删除取消该会话未完成的访谈、创建和自动保存任务，保留构思和历史；恢复不会自动重启已取消的任务。删除与恢复都记录撤回凭据，可在运行历史逐次撤回。

`GET /api/drafts?deleted=true` 查询回收站草稿。旧版仅保留访谈、尚无 `setup_drafts` 行的会话也支持删除，不会因历史发现逻辑重新出现在书架中。

## 永久删除

回收站中点击「永久删除」，明确确认后调用：

- `DELETE /api/drafts/{draft_id}`
- `DELETE /api/stories/{story_id}`

接口只接受已移入回收站的对象。清理范围包括正文与人物聚合、全部版本与分支、字段事件与快照、检索向量、创建前草稿与访谈、全部关联命令与事件、撤回凭据、作品提示词绑定与版本，以及命令中保存的 agent 状态。删除小说时同时清理其创建会话；删除撤回创建后留下的草稿时，一并清理已隐藏的关联小说。关联会话中若仍有活跃小说则拒绝清理。

永久删除是同步的专用服务操作，刻意不提交新的持久命令或撤回记录，以免清理运行历史后又留下包含作品信息的新历史。返回 `PurgeResult` 中的命令 ID 供队列清理，关联对象、版本和会话 ID 供浏览器清理未发送输入及重新生成草稿缓存。不会清理其他作品或全局字段、提示词模板。

PostgreSQL 内的业务数据和 agent 状态在同一事务删除。事务使用作用域锁和非阻塞 Worker 命令锁，若后台仍持有执行锁，返回冲突并保留数据，用户稍后重试即可。正常情况下同时清除 Redis 等待、处理中队列及投递标记；Redis 不可用时可能暂留无内容的命令 UUID，Worker 遇到已不存在的命令会忽略，不能重建作品。

`resource_deletions` 对永久删除对象及命令只保留 UUID 和 `purged` 标记，不保留标题、正文、提示词、用量或操作历史。此屏障用于拒绝旧标签页的自动保存、原命令重放和迟到请求。永久删除不可撤回；再次删除同一 ID 返回成功。

验证：`tests/test_lifecycle.py` 包含 SQLite 和可选 PostgreSQL 测试；`tests/web_vue_lifecycle.test.cjs` 使用静态前端与完全拦截的合成 API，验证桌面和移动端删除、恢复、取消、失败重试及浏览器缓存清理。
