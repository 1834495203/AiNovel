# 自定义字段、模板与历史

## 升级

停止 API 和 Worker，执行 `ainovel init-db`，再重启。初始化会增加 `field_templates`、`field_template_sets`、`field_changes`、`field_snapshots` 等新表，不清空小说或历史版本。

旧小说按原版本快照读取并转换字段；首次产生新修改时保存旧版本的字段基线。旧版本没有记录过的操作无法凭快照还原为真实 patch，不会伪造历史。新版本开始完整保存增量事件。

## 字段

小说、世界观、角色档案、角色状态、偏好、创作工作区、章节和幕都可以承载递归自定义字段。实体 ID、姓名/标题、章节归属、正文、执行状态等仍由业务模型管理。

`FieldDefinition` 定义名称、解释、类型、必填标记、枚举选项、对象子字段或列表项结构。类型包括文本、数字、布尔、枚举、对象、列表和 UUID 引用。对象可选择是否允许扩充。必填标记用于描述填写要求，创建空模板实例时允许尚未填写。

`Entry` 保存独立的值 ID、定义副本和填写内容：标量放在 `value`，对象/列表放在 `children`。`definition.description` 是填写解释；旧条目的 `description` 继续作为原有文字内容保留。稳定 ID 用于寻址，改名和排序不改变身份。引用校验 UUID 格式，目前不校验目标实体的存在性。

世界观简介、偏好及 AI 的主线、支线、伏笔、大纲、笔记等已转换为普通字段。默认模板提供原有分类及条目结构。旧 Python 属性、旧补丁契约和 HTTP 输出投影暂时保留，用于现有写作、提示词与历史兼容；这些属性不再是这三个资料容器独立存储的字段。持久化使用 `round_trip=True`，只保存规范的 `entries`。

## 模板

书架的「管理字段模板」和侧栏「字段模板」打开独立模板页（`/#field-templates`），无需先创建小说。左侧切换模板，右侧直接显示可编辑的字段；资料类别使用页内标签切换，点击「保存」直接更新当前模板，点击「新增模板」直接开始新模板。手机上使用可搜索的模板下拉框。无需先复制、展开卡片或打开抽屉；切换和刷新都会保留未保存输入。

每个字段名称左侧的箭头可展开或收起说明、选项及子字段，收起时保留名称与类型。所有层级的字段默认收起，新添加的字段自动展开；「全部展开／全部收起」作用于当前类别的整棵字段树，包括对象和列表项。切换资料类别或保存后保留展开状态；收起不修改字段数据，不触发保存命令。

模板只保存定义和填写说明，不复制填写值或值 ID。底层仍保留不可变版本；`replaces_id` 标识本次直接修改的上一版本，列表只显示当前版本，保存不会在界面增加副本。过期编辑被拒绝，可在运行历史撤回最近的保存。旧模板 ID 在创建时解析到当前版本，已有小说始终使用自己的完整副本。默认模板也可直接修改，留空选择创建的新小说使用当前默认版本。

应用模板可同时指定多个同类目标，统一校验并原子提交。当前策略是补充缺少的顶层定义，保留已有值和已使用的定义；不覆盖相同定义，也不自动升级它的子结构。可另建定义后应用。不同实体的值 ID 独立，相同模板的定义 ID 相同。

### 每部小说的模板套装

每个小说模板包含八类资料的字段定义，直接点击标签编辑对应字段。需要复用旧分类模板时，可在「导入已有字段模板」中选择。新建小说时选择一套，留空使用当前默认模板；旧的分类模板创建参数继续兼容，旧分类模板也继续用于故事资料中的单类应用。

小说在 `Story.field_template_set` 中保存完整的独立副本，包含字段解释和子结构，无需以后读取全局模板。源模板仅提供初始化状态：本书字段或本书初始化结构的新增、删除、改名和类型修改都不回写源模板；源模板另存新版本或被撤回，也不会改变已有小说。

初始角色的档案和状态在创建小说时初始化。新获批角色在写作状态中初始化档案和状态；新章节和幕在草稿确认后的提交阶段初始化。每个对象有独立值 ID，不复制其他对象的填写值。正文草稿待确认时，正式资料保持不变。已有字段被删除后，普通续写不会重新套用模板把它补回来。

故事资料中的「本书模板套装」允许为已有小说应用套装：复制新的本书初始化结构，并给已有对象补齐缺少的字段，保留已有内容与定义。「编辑本书初始化结构」只影响以后新增对象，已有角色、章节和幕在字段列表单独调整；单个对象的修改不隐式改动其他对象或本书初始化结构。旧小说没有副本时，根据已有资料派生初始结构，不重写旧版本。

「将本书结构导出为新模板」把当前小说、世界观、偏好和创作工作区的字段定义导出；角色档案、角色状态、章节与幕可各选择一个实际对象作为结构样本，也可选择本书初始化结构。导出递归读取实际字段及子字段，包含实际的新增、删除与改名，不带填写值、正文、经历、填写原因和来源场景。列表以首项结构为样本，空列表保留定义中的列表项结构。导出后以独立的模板库命令另存新套装，不覆盖原模板；永久删除来源小说也不会删除已另存的全局套装。

## 事件与快照

每次小说版本提交在同一数据库事务中追加 `FieldChangeEvent`。事件关联父版本、小说、命令、原因和时间；包含 `set`、`remove`、`order` 操作。带 ID 的列表项通过 ID 寻址，普通标量列表整体替换。递归差异覆盖整个规范小说聚合，所以正文生成、角色变化、章节/幕字段和资料编辑均会被记录。

初始版本保存快照，此后沿父链每 20 次提交生成一个新快照。读取当前状态或指定版本时，从该分支最近快照重放后续事件。**快照不会删除、覆盖或压缩旧 patch。** 撤回移动有效版本指针，操作日志和旧事件保留；撤回后继续编辑产生同一历史父版本的另一条路径，恢复时不混入兄弟分支事件。

原有 `revisions` 全量版本暂时继续保存，供旧接口和历史兼容使用；`Store.head`、`Store.revision` 的故事状态通过新事件链恢复。快照、事件和保留的版本目前会占用额外空间，未启用自动清理。

## 接口与工具

- `GET /api/field-templates`：默认及自定义分类模板、`template_sets` 小说套装、模板库操作范围 ID。
- `GET /api/stories/{id}/field-template-set`：本书独立初始化结构，或旧小说的派生结构。
- `POST /api/stories/{id}/field-template-set/export`：按指定版本与来源对象只读提取新套装；客户端通过模板库命令保存。
- `GET /api/stories/{id}/fields?scope=...&entity_id=...`：某一对象的当前字段。
- `GET /api/stories/{id}/field-history?revision_id=...&limit=...`：沿指定版本父链读取事件。下一页传最后一条的 `parent_id`。
- 字段命令包括 `save_field_template`、`apply_field_template`、`edit_fields`；套装命令包括 `save_field_template_set`、`initialize_story_template_set`、`update_story_field_schema`。本书结构随版本和字段历史保存，支持撤回。
- 故事讨论新增可选 `edit_fields` 工具，整轮修改成功后统一提交，并支持撤回。

本次仅改造字段、模板和历史基础；写作图、正文草稿确认、幕规划及历史幕编辑策略沿用现有行为。
