# 幕设定与正文写作

小说有两个独立页面：`/#planning/{story_id}` 是幕设定，`/#story/{story_id}` 是正文写作。原故事讨论入口已替换为幕设定。旧小说、旧字段模板及历史数据已清空，不再迁移。

幕设定页左侧展示当前路线或全部幕与分支，选中幕可查看完整内容、发起修改或从此分支；右侧管理多个设定会话。所有设定会话共享小说的幕计划，每个会话独立保存消息。一次请求可批量创建或修改多幕，普通讨论也可只回复。设定直接保存，不存在草稿审批，使用普通 agent loop。

设定助手使用普通 agent loop，工具由模型按需选择：

- `search_story(query)`：查找已写正文，返回前文片段。
- `save_scene_plans(create, update, select_leaf_id)`：每次最多新增 40 幕、修改 40 幕，也可只切换路线。`create` 的每幕包含 UUID、父幕 UUID、标题、简单剧情、参与人物及是否新章；同批次先提交父幕再提交子幕。`update` 通过 UUID 修改标题、剧情及参与人物，不允许修改已写幕。同父幕的多个子幕构成分支。`select_leaf_id` 选择路线终点，不能改变已写正文前缀。

工具先在本轮隔离副本执行。校验失败作为工具结果返回，模型可修正后继续；直到回复才将本轮成功的修改和会话回复一次提交。重复工具调用会提前停止；达到循环上限时保存已完成的有效修改，并明确提示未完成部分，避免整轮结果丢失。多个会话发生并发更新时，通过小说版本校验拒绝覆盖，用户刷新后重试。

写作只能沿当前路线生成已有的下一幕。正文 agent 按需读取资料，通过工具一次提交正文、摘要及实际变化，不自动串联规划、人物访谈、审阅、提取等模型步骤。只有正文存在待确认草稿；确认只是数据库提交，不调用模型。已写幕锁定计划，修改或重写正文仍使用同一个写作 agent。

设定会话保存造成小说修改，因此和正文写作共用小说级撤回顺序，避免回退一个旧会话时覆盖另一个会话的新资料；只能回退最新操作。旧只读讨论继续使用独立会话撤回栈。正文、幕与会话内容均随小说永久删除清理。

设定 loop 使用原生 assistant tool_calls / tool 消息配对。基础上下文只包含世界规则、人物姓名、近期正文摘要和幕列表，不发送字段定义、完整人物快照或创作工作区副本；会话历史保留最近八条，每条最多 1500 字符。旧小说已写正文的幕可直接作为新幕的父节点，无需补建历史计划。
