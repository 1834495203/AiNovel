# 角色演绎工作区

本设计以用户确认的 2026-11-03 规格为准。五类资料：世界观、角色、创作、章节、幕；统一 Entity/Description/Attribute，描述和属性均有 0（仅 GM）、1（仅本人）、2（公开）可见性。内部 ID 由程序创建。

创建小说采用渐进式对话编辑，用户确认建书。每幕一个工作会话，用户/GM 与角色群聊两个窗口；只有当前路线最新幕能继续编辑。用户确认前都是演绎尝试，确认后可创建下一幕；修改旧幕必须分支。普通聊天不允许写入。

创建前采用独立的 AI 构思页面，不展示角色群聊或幕目录。必须至少完成一轮用户/AI 交流后才能确认建书。未确认的数据是构思草稿，单独展示以便继续。全局字段模板支持直接编辑五类实体的描述与变量；创建时仅补充缺少的初始字段，保留对话已有修改。每本书保留模板独立副本供新角色/章节/幕初始化，字段修改不会反写模板。本书当前字段可导出为新模板。

GM 八种工具：对用户发言、在群聊发言、顺序调度角色、修改字段、重置、入场、离场、新建角色（默认不入场）。每次工具返回 GM；对用户发言不释放执行权；模型不再调用工具、自然结束后允许用户发送。顺序调度的角色提交行动意图，执行结束后由 GM 描述结果；需要根据已裁定结果反应时，分两次调度。

进出场本身是群聊事件，不另存曾经出场名单；消息记录发送时的接收者。角色上下文只包含自己的历史状态、自己在场区间内可见的事件和当前调度，不携带用户与 GM 的幕后讨论、小说全局资料、其他角色私密字段或未来幕。变量和描述都先过滤后渲染 Jinja；0 不向角色发送，1 只向本人发送，2 仍受实际在场范围限制。

设定编辑与演绎状态独立：重置保留世界观、人物设定、创作要求和幕设定，废弃当前群聊/进出场及演绎状态变化。被废弃尝试保留供用户查看，不进入模型上下文。角色只能修改自己的可见字段或离场；不能借修改字段越权读取隐藏内容、修改别人或自行裁定客观结果。

角色状态在幕间以周期快照和 patch 回放；其他资料使用全局当前值。用户修改已确认历史状态必须分支。确认演绎和生成正文是独立动作；写作只接收已确认幕和对应状态，直接保存正文，无草稿审批。正文可重写，只能撤回当前路线最后一份正文。

章节完成由用户明确标记，自动生成系统摘要；正文变更使摘要失效。上下文按最近完整章节数、之后幕级章节数、其余章节摘要分级；摘要缺失时回退完整内容，不静默截断。下一次请求预览包括行为模板、上下文、历史和工具 schema 的估算 token，实际用量累计保存。角色的在场历史不通过小说章节压缩规则泄露其他内容。

默认边界：重置整幕演绎；GM 不替角色决定；用户通过设定/重置改变演绎方向；同一时刻一轮执行，预算耗尽保留进度并暂停。错误保留已经记录的工具结果，不自动重复执行副作用。提示词与上下文使用前端可编辑的 Jinja，Pydantic 工具 schema 独立导出。
