# 纸间 · AI Novel MVP

一个可运行的小说创作工作台：通过对话确认小说设定，在聊天中生成场景，阅读正文、采访不同阶段的角色，并以可回溯的版本管理修改。

Python 3.12+；FastAPI + SQLAlchemy 2 + Pydantic 2 + PostgreSQL/pgvector + Redis；前端使用 Vue 3、TypeScript 和 Vite。Vite 构建产物随 Python 包提供，由 FastAPI 统一服务，运行时不需要单独启动 Node。默认本地单用户使用。

## 启动

已有 PostgreSQL、Redis 可以直接使用。仓库的 docker-compose.yml 保留了你的数据库配置。

```powershell
# 如果数据库容器尚未运行
# 首次启动先复制配置，并将 POSTGRES_PASSWORD 与 DATABASE_URL 中的密码改为同一个自选值。
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up -d

# 本次已在 .venv 安装完成；重新安装时仍使用清华镜像
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt -i https://pypi.tuna.tsinghua.edu.cn/simple/
.\.venv\Scripts\python.exe -m pip install -e . --no-deps -i https://pypi.tuna.tsinghua.edu.cn/simple/

# 首次使用且没有 .env 时才复制；已有配置保留
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\ainovel.exe init-db
```

两个终端分别运行：

```powershell
.\.venv\Scripts\ainovel.exe api
```

```powershell
.\.venv\Scripts\ainovel.exe worker
```

打开 [工作台](http://127.0.0.1:8000)，[API 文档](http://127.0.0.1:8000/docs)，[运行状态](http://127.0.0.1:8000/health)。状态接口会区分 PostgreSQL、Redis 和 Worker。API 默认监听 `0.0.0.0:8000`；同一局域网或连接本机移动热点的设备，通过本机对应网卡的 IPv4 地址加 `:8000` 访问。Windows 防火墙需允许本地子网访问 TCP 8000。

可以直接编辑未跟踪的 `.env`，设置 `ACCESS_PASSWORD="你设置的访问密码"`（8–256 个字符），重启 API 后生效。`ACCESS_PASSWORD` 非空时优先使用它；留空则使用原有 `ACCESS_PASSWORD_HASH`，两项都留空才关闭访问保护。也可运行 `.\.venv\Scripts\ainovel.exe set-password` 交互设置哈希密码，该命令会清空明文配置，避免覆盖冲突。修改密码会使原登录失效，需重新登录；浏览器登录默认有效 12 小时，顶部提供退出登录。

init-db 创建 MVP 数据表与 pgvector 扩展，可重复执行；创建扩展需要数据库用户有对应权限。正式部署前应换成明确版本的迁移管理。

## 使用流程

首页已切换为角色演绎工作区，使用 `/api/studio` 接口。

前端使用 Vue 3、Naive UI 和 Lucide 图标重新实现。手机底部切换对话、设定、演绎和正文，目录与设置使用抽屉；桌面同时显示目录、对话与演绎。聊天输入框紧接消息区，独立滚动的消息列表不会把输入框挤出屏幕。发送后立即显示用户消息与运行进度，后台回复自动更新；失败保留输入并提供重试，切换页面也会保留未发送内容。输入框兼容软键盘缩小后的视口，手机 Enter 换行，桌面 Enter 发送、Shift+Enter 换行。

1. 先进入独立的 AI 构思页面，可选择字段模板，与助手逐步交流并修改设定。确认后才创建正式小说；未确认内容保存为构思草稿。
2. 创建第一幕，在“你与 GM”和“角色群聊”两个窗口中创作。新人物默认不入场。
3. GM 可向用户/群聊发言、顺序调度角色、编辑字段、重置、安排入场/离场、新建人物。向用户发言后可以继续调用工具；模型不再调用工具、本轮结束后用户才能继续发言。
4. 角色只读取自己的可见字段和在场区间内的消息，自主选择行动；可修改自己的可见字段或主动离场，GM 描述客观结果。
5. 重置保留世界观与设定编辑，废弃本次演绎及临时角色变化。满意后确认本幕，随后创建下一幕。修改旧幕通过分支进行。
6. 正文页面依据已确认演绎直接生成或重写正文，无额外草稿审批。正文按顺序回退；章节完成后生成系统摘要。

资料分为世界观、角色、创作要求和章设定。描述和属性均有 0（仅 GM/系统）、1（仅本人）、2（公开）可见性。角色状态使用周期快照和逐幕补丁。GM 演绎和正文写作读取当前章设定，本幕的具体要求可在 GM 对话中交代。

GM 的用户讨论和角色群聊是两个独立频道。用户讨论历史标记为 `user_discussion`，当前群聊事件标记为 `character_group`；GM 的普通回复、调用工具时附带的文本和 `say_to_user` 都发给现实用户，角色看不到；`say_to_group` 只发送角色可感知的场景、台词和客观结果。两个工具具有独立的说明及参数描述，返回值包含实际目标频道。模型回复中没有工具调用时，显示非空的普通回复并自然结束，不额外追问或调用结束工具。创建助手和角色的直接回复行为不受此限制影响。



顶部“字段模板”提供全局模板的新增、切换、直接编辑、保存与删除。模板定义各类资料的描述字段和变量初始值。创建前可为构思初始化独立副本，新建角色和章节继承本书模板。本书当前字段可另存为新模板。

上下文设置可调整完整章节数、幕级章节数、调用预算和角色快照间隔，实时预览预计输入 token。更早章节使用摘要；缺少有效摘要时保留完整内容，不静默截断。行为与上下文使用可编辑 Jinja，工具参数/返回值由 Pydantic 单独导出。

每轮执行保存进度并锁定输入，失败或预算耗尽后交还用户。重启不会自动重跑付费调用。回收站支持恢复；永久删除会清除该书的设定、角色、演绎、废弃尝试、分支及正文。旧数据不会被自动清空。

GM 可以使用 `rewind_performance` 逐步回撤或回到指定操作/群聊位置。底层保存每幕的起始状态及仅含正向修改的操作链：当前位置决定从起点执行到哪一步，不需要逐项编写逆操作。回溯同时恢复字段、角色自改状态、进出场和在场人数；用户讨论与调用统计保留。回撤后继续会形成新路径，原路径保留。群聊条目显示 `#序号` 方便指定位置；已确认幕需先分支。记录启用前的旧内容无法凭空还原，回溯从开始记录的位置起生效。

模型一次回复可以包含多个工具，系统先校验整批参数，再按返回顺序执行，并逐一回传结果；暂停、重置或角色离场后跳过本批次后续操作。创建会话和最新未确认幕的最后一条用户消息下提供重试、修改和撤回。重试/修改先恢复本轮开始前的资料与演绎，再运行模型；撤回恢复状态并删除本轮对话，调用次数和已用 token 保留。服务只保留最新一轮的完整回退检查点，检查点不发送到前端或模型。之后发生的手动修改、确认、新幕或分支会使旧检查点失效；升级前的消息没有检查点，不能可靠撤销其工具效果。回退能力不会推测或伪造旧状态。

无检查点的旧消息仍可修改、重试或撤回聊天，但需要明确确认保留当前资料、角色状态和演绎。该操作只移除最后一条用户消息及其后的 AI 回复，重试/修改在当前状态上重新调用模型，并为新一轮建立检查点；不会伪造旧消息对应的历史状态。此方式不能绕过新消息的版本保护或已确认幕的冻结限制。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -m pytest -q
npm run typecheck
npm run build
```

`tests/test_studio.py` 使用离线模型和隔离 SQLite，覆盖可见性、重置、分支、快照、调度、并发锁与完整 API 流程。浏览器回归 `tests/web_studio.test.cjs` 只允许运行在 mock 站点，默认使用 8002 端口。

新版前端的浏览器回归入口为 `tests/web_studio.test.cjs`、`tests/web_studio_templates.test.cjs` 和 `tests/web_mobile_interaction.test.cjs`，设置 `AINOVEL_STUDIO_BROWSER=1` 后通过 `node --test` 运行。使用隔离数据库的 mock API，覆盖手机 320/390px、软键盘高度、即时发送反馈、失败重试、模板独立性、角色演绎、正文与分支，并模拟局域网 HTTP 不提供 `crypto.randomUUID` 的环境。旧版页面的浏览器脚本不适用于此入口。

新工作区规格与默认边界见 [角色演绎工作区](docs/gm-workspace.md)。
